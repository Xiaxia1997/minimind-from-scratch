# 12 - 梯度累积（Gradient Accumulation）

> 源码位置：`trainer/train_pretrain.py:38-49, 93`
> 同样模式出现在：所有 trainer 脚本

## 一句话总结

显存不够开大 batch？把 N 个小 batch 的梯度累加起来再更新一次，数学上等价于 N 倍大 batch。

## 为什么需要梯度累积

大 batch size 的好处：
- 梯度估计更稳定（更多样本的平均）
- 学习率可以开更大（linear scaling rule）
- 训练更快收敛

但 GPU 显存有限（4060 只有 8GB），batch size 开不大。

**梯度累积 = 时间换空间**：用 N 次前向反向的时间，换取 N 倍 batch size 的效果。

## MiniMind 中的实现

```python
# train_pretrain.py:38-49
loss = loss / args.accumulation_steps      # ① 提前除以 N，这样累加后等价于 mean

scaler.scale(loss).backward()              # ② 每步都反向，梯度自动累加到 .grad

if step % args.accumulation_steps == 0:    # ③ 每 N 步才更新一次
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(...)
    scaler.step(optimizer)
    scaler.update()
    optimizer.zero_grad(set_to_none=True)  # ④ 更新后清零，开始下一轮累积
```

默认 `accumulation_steps=8`（预训练）/ `1`（SFT）。

## 数学等价性

假设 batch_size=4, accumulation_steps=2：

```
等效 batch size = 4 × 2 = 8

正常大 batch:    loss = (1/8) × Σᵢ₌₁⁸ L(xᵢ)
                 grad = ∂loss/∂w

梯度累积:        loss₁ = (1/8) × Σᵢ₌₁⁴ L(xᵢ)    ← 注意是除以 8 不是 4
                 grad₁ = ∂loss₁/∂w
                 loss₂ = (1/8) × Σᵢ₌₅⁸ L(xᵢ)
                 grad₂ = ∂loss₂/∂w
                 grad_total = grad₁ + grad₂        ← PyTorch 自动累加

两者的 grad_total 完全一样！
```

关键：**loss 要除以 accumulation_steps**（第 38 行），否则梯度会被放大 N 倍。

## 处理最后一个 epoch 的残余步

```python
# train_pretrain.py:75-80
if last_step > start_step and last_step % args.accumulation_steps != 0:
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), args.grad_clip)
    scaler.step(optimizer)
    scaler.update()
    optimizer.zero_grad(set_to_none=True)
```

如果最后几步不够 N 步凑一轮，也要把已累积的梯度更新掉，不能丢。

## 和分布式训练的关系

```
单卡梯度累积:  等效 batch = batch_size × accumulation_steps
DDP:          等效 batch = batch_size × num_gpus
两者组合:     等效 batch = batch_size × accumulation_steps × num_gpus
```

MiniMind 预训练默认：batch_size=32, accumulation_steps=8 → 等效 batch=256。
如果用 2 卡 DDP → 等效 batch=512。

## 注意事项

1. **BatchNorm 不兼容**：BN 统计量按小 batch 算，累积不能修正。MiniMind 用 RMSNorm 没有这个问题。
2. **Dropout 行为**：每个小 batch 的 dropout mask 不同，这其实引入了额外随机性，实践中影响很小。
3. **学习率调整**：如果改了 accumulation_steps，等效 batch 变了，学习率也应该按比例调（linear scaling rule）。

## 面试话术

> 梯度累积是显存不足时的标准优化手段：把 N 个小 batch 的梯度累加再更新一次，
> 数学上等价于 N 倍大的 batch size。关键实现细节是 loss 要提前除以 N，
> 否则梯度会被放大。在 MiniMind 的预训练脚本里，默认 accumulation_steps=8，
> 配合 batch_size=32 等效于 256 的大 batch。
> 还要注意处理 epoch 末尾不够 N 步的残余梯度，MiniMind 有专门的尾部 flush 逻辑。
