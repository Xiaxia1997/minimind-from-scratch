# 10 - 混合精度训练（AMP）

> 源码位置：`trainer/train_pretrain.py:35-49, 91, 120-122, 137`
> 同样模式出现在：`train_full_sft.py`, `train_dpo.py`, `train_grpo.py`

## 一句话总结

用低精度（bf16/fp16）做前向和反向加速计算，用 FP32 做权重更新保持精度，两全其美。

## 为什么需要混合精度

| 精度 | 位数 | 显存占用 | 计算速度 | 数值范围 |
|------|------|---------|---------|---------|
| FP32 | 32 bit | 基准 | 基准 | ±3.4×10³⁸ |
| FP16 | 16 bit | 1/2 | 2-3x | ±6.5×10⁴（容易溢出） |
| BF16 | 16 bit | 1/2 | 2-3x | ±3.4×10³⁸（和 FP32 一样） |

核心收益：
1. **显存减半**：激活值、梯度都用 16 bit 存储，batch size 可以开更大
2. **计算加速**：GPU Tensor Core 对 16 bit 矩阵乘法有专门优化（A100 上 bf16 约 2-3x 快于 fp32）
3. **通信减半**：分布式训练时梯度同步的数据量减半

## MiniMind 中的完整实现

### 第一步：创建 autocast 上下文和 GradScaler

```python
# train_pretrain.py:120-122, 137
dtype = torch.bfloat16 if args.dtype == "bfloat16" else torch.float16
autocast_ctx = torch.cuda.amp.autocast(dtype=dtype)    # 前向自动低精度
scaler = torch.cuda.amp.GradScaler(enabled=(args.dtype == 'float16'))  # 只 fp16 需要
```

### 第二步：训练循环中使用

```python
# train_pretrain.py:35-49
with autocast_ctx:                              # ① 前向：自动选算子精度
    res = model(input_ids, labels=labels)
    loss = res.loss + res.aux_loss
    loss = loss / args.accumulation_steps

scaler.scale(loss).backward()                   # ② 反向：缩放 loss 防梯度下溢

if step % args.accumulation_steps == 0:
    scaler.unscale_(optimizer)                  # ③ 恢复原始梯度值
    torch.nn.utils.clip_grad_norm_(...)         # ④ 在原始尺度上裁剪
    scaler.step(optimizer)                      # ⑤ FP32 权重更新
    scaler.update()                             # ⑥ 动态调整 scale factor
    optimizer.zero_grad(set_to_none=True)
```

### 第三步：保存时转 FP16

```python
# train_pretrain.py:68
torch.save({k: v.half().cpu() for k, v in state_dict.items()}, ckp)
# 训练时权重是 FP32（master weights），保存时压缩到 FP16 节省磁盘
```

## autocast 做了什么（算子级自动选择）

`torch.cuda.amp.autocast` 不是把所有运算都变成低精度。它有一个**白名单/黑名单**：

| 走低精度（bf16/fp16） | 保持 FP32 |
|----------------------|-----------|
| 矩阵乘法（Linear、Conv） | Softmax |
| BMM（注意力的 Q·K 和 attn·V） | LayerNorm / RMSNorm |
| Embedding lookup | Loss 计算（cross_entropy） |
| | 指数/对数运算 |

原则：**计算密集型 → 低精度加速，精度敏感型 → FP32 保精度**。

MiniMind 的 RMSNorm 里 `.norm(x.float())` 也有类似考虑——先转 FP32 再算均方根。

## GradScaler 的工作原理（只有 FP16 需要）

### 问题：FP16 的梯度下溢

FP16 最小正数 ≈ 6×10⁻⁸，很多梯度值小于这个值 → 直接变成 0 → 训练崩溃。

### 解法：动态缩放

- 前向：$\text{loss\_scaled} = \text{loss} \times \text{scale\_factor}$（比如 $\times 65536$）
- 反向：梯度也被放大了 $\times 65536$，不会下溢
- 更新前：`scaler.unscale_()` 把梯度除回来 $\div 65536$

scale_factor 的动态调整：
- 连续 N 步没有 inf/nan → scale_factor × 2（放大，榨取更多精度）
- 出现 inf/nan → scale_factor / 2（缩小，避免溢出），并跳过这步更新

### 为什么 BF16 不需要 GradScaler？

```python
scaler = torch.cuda.amp.GradScaler(enabled=(args.dtype == 'float16'))
#                                   enabled=False when bfloat16
```

BF16 的指数位和 FP32 一样（8 bit），数值范围相同（±3.4×10³⁸），不会下溢。
FP16 只有 5 bit 指数位，范围小得多，必须用 scaler 防下溢。

## BF16 vs FP16 详细对比

```
FP32:  1 bit 符号 + 8 bit 指数 + 23 bit 尾数  → 高精度高范围
BF16:  1 bit 符号 + 8 bit 指数 +  7 bit 尾数  → 低精度高范围（砍尾数保指数）
FP16:  1 bit 符号 + 5 bit 指数 + 10 bit 尾数  → 中精度低范围（砍指数保尾数）
```

| | BF16 | FP16 |
|--|------|------|
| 数值范围 | 同 FP32 | 远小于 FP32 |
| 精度 | 较低（7 bit 尾数） | 较高（10 bit 尾数） |
| 需要 GradScaler | 不需要 | 必须 |
| GPU 支持 | A100+ / RTX 30系+ | 所有有 Tensor Core 的 GPU |
| 训练稳定性 | 更稳定 | 需要调参 |

**结论：优先用 BF16**（如果 GPU 支持），这也是 MiniMind 的默认值。

## Master Weights 概念

训练中实际有**三份权重**：
```
master weights (FP32) ← optimizer 持有，更新在这上面做
model weights (FP32)  ← model.parameters()，autocast 时自动转低精度
saved weights (FP16)  ← 保存检查点时转 half()，推理时加载
```

为什么 optimizer 要用 FP32？
- 权重更新 = weight - lr × gradient
- lr = 1e-5，gradient 可能也很小
- 低精度下 `weight - 0.00001 × 0.001 = weight`（精度不够直接被舍掉）
- FP32 下能正确累加这些微小更新

## 面试话术

> 混合精度训练的核心是"前向反向走低精度加速，权重更新走 FP32 保精度"。
> autocast 自动按算子类型选精度：矩阵乘法走 bf16 加速，softmax/loss 保持 FP32。
> 如果用 FP16，还需要 GradScaler 做动态缩放防止梯度下溢——因为 FP16 指数位只有 5 bit，数值范围太小。
> BF16 保留了 FP32 的 8 bit 指数位所以不需要 scaler，这也是目前业界默认选择。
> 在 MiniMind 里我看到 GradScaler 的 enabled 参数根据 dtype 动态开关，
> 保存检查点时用 `.half()` 把 FP32 master weights 压缩到 FP16 节省磁盘。

## 业界对比

| 模型 | 训练精度 | 特殊处理 |
|------|---------|---------|
| MiniMind | BF16（默认）/ FP16 | GradScaler 按需启用 |
| LLaMA-3 | BF16 | 无 GradScaler |
| Qwen2.5 | BF16 | 部分用 FP8（H100 上） |
| DeepSeek-V3 | FP8 (E4M3) + BF16 | 前向 FP8 加速，反向 BF16 |
| GPT-4 | 推测 BF16 + FP8 | 未公开细节 |

趋势：从 FP16 → BF16 → FP8，精度越来越低但用更精细的量化策略弥补。
